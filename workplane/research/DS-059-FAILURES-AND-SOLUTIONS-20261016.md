## Product identity

Google's current variant documentation describes brand and other shared properties on ProductGroup, while variants carry their own identifiers, selections and offers. Schema.org's isVariantOf documents non-transitive inheritance. Current code traverses hasVariant and resolves selected children, but then reads brand/material only from that child. Selected identity is lost when the common data is correctly stored on its group. Implement only one explicitly connected parent, child override precedence, no inheritance of a variesBy dimension, and no parent GTIN/MPN/SKU/offer/price inheritance. Resolve uniquely identified local group/Brand nodes within the already bounded JSON-LD graph; never fetch a reference or follow ancestry chains. Ambiguous ancestry/IDs abstain.

Primary sources, retrieved October16: https://developers.google.com/search/docs/appearance/structured-data/product-variants ; https://schema.org/ProductGroup ; https://schema.org/isVariantOf ; https://schema.org/brand .

The extraction path also omits typed Microdata identifiers, even though Product can be expressed in that format. Add a tightly bound public Product scope with current-URL/name agreement, no unresolved variant selection, and unique explicit brand/MPN/GTIN values. Exclude nested/related products, reviews, hidden/CSS-hidden/private/form/control regions; preserve already bound JSON-LD fields. A model or store-local SKU is not a global MPN. GS1's check digit establishes structural integrity, while registry ownership/product verification is a separate service: validate the numeric checksum for fallback GTINs without claiming registry validation. GS1's expanded/API access requires an external arrangement and is not a free runtime dependency.

Primary sources: https://www.schema.org/Product ; https://www.gs1.org/services/check-digit-calculator ; https://www.gs1.org/services/verified-by-gs1 ; https://support.gs1.org/support/solutions/articles/43000734070-how-do-i-check-if-a-gs1-gtin-is-valid- .

## Scarcity precision

The FTC's September2022 primary report distinguishes baseless countdowns/renewed deadlines from merely displayed low-stock wording. Existing history analysis upgrades any repeated scarcity phrase to a strong warning after two days, including legitimate unchanged stock. It also counts the present wording and history finding as independent. Preserve an explicit sale/offer countdown in passive evidence; compare observation timestamps plus valid HH:MM:SS durations, and report repeatedly moving implied deadlines. Ordinary decreasing clocks, malformed clocks and static low stock must not acquire this warning. Correlate the historical finding with its current observation so it counts once. Record real observation provenance; no elapsed time is invented. This is a manipulation finding, not proof of dropshipping or a severe provenance accusation.

Primary report: https://www.ftc.gov/reports/bringing-dark-patterns-light (September2022). The supplier-direct disclosure remains neutral: Shopify's own definition describes a fulfillment model, not merchant fraud: https://help.shopify.com/en/manual/products/dropshipping/what-is-dropshipping .
