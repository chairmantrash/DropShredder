# Merchant-language support

DropShredder supports English plus Simplified Chinese, Hindi, Spanish, Modern Standard Arabic, French, Bengali and Portuguese commerce cues offline. Page language and Chrome's interface language are independent. This is a finite detection vocabulary and Unicode handling, not an automatic page translator or a guarantee of equal accuracy on every site.

Supported surfaces include native-language purchase labels, product/search/editorial/account path aliases, credential/payment fields and scoped private form destinations, current-product JSON-LD identity, original-script hero/title matching, localized visible prices with declared page language and explicit ISO currency, delivery ranges and urgency, return costs/windows/fees and contextual negation, maker/partner/quality/origin vocabulary, original-script review similarity/incentives/complaints, Gregorian review dates, explicit variant names/values, technical materials/units, local lexical search and original-language source queries. Exact barcode/model/brand identities, cryptographic keys, API payloads and merchant quotations are not machine-translated. All severe gates, weights, independence rules and geographic neutrality remain unchanged.

Structured Product/Offer property names and machine prices remain schema vocabulary: ASCII digits and dot decimal. Localized display price parsing is separate. Ambiguous separators without language, price ranges, multiple price nodes and variant ambiguity stay unresolved. A modeled browser-translated DOM can retain a single original schema identity when unchanged original OpenGraph metadata independently matches it; conflicting recommendations or ambiguous variants still abstain. The displayed heading and original structured title are retained separately in that case.

The local reader has explicitly selected eng/chi_sim/hin/spa/ara/fra/ben/por models, loaded from the package only after READ LABEL ON DEVICE. Non-English OCR also loads English for Latin SKU text. No photo upload or runtime model download. Recognized text is unverified and never changes seller scores. Selected photos and text are not automatically saved. The models add6,646,038compressed bytes; pinned source/license/hash provenance is in intelligence/ocr-models.json (pinned originals) and generated public/ocr/LANGUAGE-MODELS.json (package hashes) and LICENSE-TESSDATA-FAST.txt.

The kit is `src/languages/commerce-kit-data.json`, with source-span mapping in commerce-text.ts, finite date handling in commerce-date.ts and serialized scanner arguments. Add contextual aliases and independently authored positive, negative, privacy and ambiguous fixtures together. Don't derive expected fixtures from the dictionary. Review exact quotations, equal evidence IDs/weights, attribution, unknown outcomes and work budgets. Never strip Indic combining marks to fit an ASCII tokenizer or infer an exact identifier from translation.

Verification uses core fixtures, seven genuine Chrome UI locale profiles, English-profile native scans/toasts/manual repeats on equivalent original-language pages, modeled translated DOM, private/search paths, a bounded large page and actual selected OCR invocation on synthetic script labels. Browser results are authoritative only once the current source/package is fingerprinted and its workflow passes. Fixtures and synthetic labels are not representative merchant/category calibration, independent photo accuracy, a real Google Translate service test or native-speaker review. APIs keep their original scope/geographic limits; no broader recall clearance is implied. Supported language vocabularies cannot cover all idioms, calendars or storefront implementations.
